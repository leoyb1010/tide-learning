## 产品角色与预期边界

`prisma/schema.prisma` 的 User.role 与 `src/lib/session.ts` 定义以下真实角色。订阅者、作者、买家是权益/所有权状态，不是额外后台角色。

| 角色 | 正常职责 / 授权 | 关键禁止路径 |
| --- | --- | --- |
| user | 学员档案、本人学习申请 | 全部 8 个后台权限、权限矩阵 |
| admin | 全部 8 权限、权限矩阵 | 会话过期后全部禁止；角色降级后按新角色判断 |
| content_manager | 课程写入、看板 | 审核、订单、退款、用户/建联与角色配置 |
| demand_moderator | 需求审核、看板 | 内容审核、课程写入、财务、角色配置 |
| support | 用户查询、建联、订单读取 | 退款/积分调账、内容写入、权限矩阵 |
| finance | 订单读取、退款/积分调账、看板 | 用户管理、内容审核、课程写入、角色配置 |
| reviewer | 内容审核 | 需求审核、课程写入、财务、用户管理、权限矩阵 |

所有权限以 DB 覆盖优先，未覆盖角色才回退默认。对角色移除最后一项授权必须保留覆盖标记。

## 第一轮：实际职责、拒绝路径与角色交接

- 7 个角色逐一验证所有 8 个权限及 admin 专用管理入口；匿名应为 401，已登录越权应为 403
- 学员申请必须绑定当前登录学员和数据库中的课程作者，不能接受伪造 requesterId/ownerId
- 作者已批准的申请重试应返回持久化决策，不重复通知
- 在旧权限查询尚未完成时撤销 reviewer 权限，再完成旧查询，复现撤销被旧快照覆盖
- 在申请创建中注入存储故障，复现“实际没有保存却返回申请成功”

## 第二轮：对第一轮修复进行并发、重试和中断挑战

- 强制刷新与普通查询共享旧请求时，全部等待者必须在失效后读取新代次
- 多次失效与多个并发强制读取最终收敛到最新撤销，不能重新发布较早授权
- 撤销后的数据库故障必须返回 503，不能回退旧权限；角色切换与会话失效重新核对当前身份
- 唯一键冲突后读取同一课程/同一申请者的真实获胜行，保持 approved/rejected，不虚构 pending
- 冲突后找不到匹配行、非唯一键错误保持失败；故障后的正常重试可以成功，只通知一次
- 错误 JSON 类型与参数类型返回可恢复 400，不触发未预期 500
- 浏览器合成场景覆盖权限侧栏、越权深链、打开页面期间撤销、刷新/Back、角色降级与会话过期；使用真实页面/API和测试数据库，未模拟页面响应

## 复现与修复

### TIDE-R1：撤销权限被飞行中的旧读取恢复

路径：权限管理写入 → invalidatePermissionCache → primePermissionCache → hasPermission / 页面与 API 守卫。

修复前，撤销后强制读取仍等待同一旧 Promise；旧查询完成后重写缓存和时间戳，令 reviewer 恢复 content:review。原始回归测试出现 2 个失败：撤销后权限仍为 true，以及后续数据库故障时读取仍 fulfilled。

修复：为缓存失效引入代次；旧代次读取不能发布，全部等待者共同等待最新代次刷新。保留短缓存/查询合并、默认矩阵和故障时 503 行为。没有承诺跨进程瞬时撤销：其他工作进程仍遵循原有 10 秒 TTL。

### TIDE-R2：学习申请错误被当成重复点击成功

路径：POST /api/market/request → courseAccessRequest.create → catch → 成功响应。

修复前，所有数据库错误都返回 pending/200；唯一键竞争中作者已批准或拒绝时也返回 pending。错误 courseId/message 类型还会导致 trim 抛出 500。原始市场回归测试共出现 6 个失败。

修复：先校验 JSON 对象及字符串参数；仅 P2002 唯一键错误允许按当前用户+课程回查；存在的申请返回真实状态和 requestId；找不到获胜行或其他错误交给统一错误处理。成功创建、既有申请和并发重复三条路径保持兼容。
